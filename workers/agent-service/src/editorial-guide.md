# 글쓰기 가이드

모든 블로그에 적용하는 기본 기준이다. 말투, 독자, 피해야 할 표현은 블로그별 작성 설정을 우선한다.

## 제목과 도입

- 제목에 독자가 해결하려는 문제나 얻을 결과를 구체적으로 담는다.
- 첫 문단은 독자에게 가장 중요한 답이나 구매·사용 판단으로 시작한다. 인기도를 근거 없이 언급하거나 글에서 무엇을 알아볼지 나열하는 문장으로 시작하지 않는다.
- 제목은 제목 필드에 한 번만 적고 도입은 소제목 없이 본문 첫 문단에 쓴다.

## 목차와 본문

- 독자가 실제로 확인하거나 행동하는 순서로 목차를 구성한다.
- 목차에는 발행 화면에서 독자가 읽을 소제목만 적는다. '제목', '도입', '본문 1' 같은 작업용 이름이나 작성 지시를 넣지 않는다.
- 소제목마다 서로 다른 독자 질문 하나에 답한다. 글 앞부분에서 설명한 특징은 뒤에서 다시 풀어 쓰지 않고, 소제목에 해당하는 판단 기준·주의점·확인 방법을 새로 제시한다. 새로 전할 내용이 없는 섹션은 목차에서 뺀다.
- 특정 제품 글은 해당 제품을 선택하거나 사용하는 데 필요한 내용을 먼저 설명한다. 제품 차이를 이해하는 데 필요할 때만 부품이나 기술 용어를 설명한다.
- 체크리스트 글은 항목마다 무엇을 확인할지, 어떻게 확인할지, 어떤 경우 주의할지 알려준다.

## 사실과 근거

- 글의 핵심 주장은 검증 가능한 사실과 근거로 작성한다. 근거가 제공되면 해당 주장을 직접 뒷받침하는 제조사 공식 문서, 기관 자료, 원자료를 우선한다.
- 사용한 근거의 문서명과 제공된 URL은 해당 주장 가까이에 적는다. 출처 제목, URL, 숫자, 인용문을 추정해서 채우지 않는다.
- 가격, 정책, 제품 사양, 지원 여부처럼 달라질 수 있는 정보는 근거가 확인해 주는 시점과 적용 범위를 함께 적는다. 근거가 부족하면 구체적인 수치나 결론을 빼거나 확인이 필요하다고 표시한다.
- 출처에서 확인한 사실과 그 사실을 바탕으로 한 판단을 구분한다. 직접 확인하거나 사용한 경험이 있는 것처럼 서술하지 않는다.

## 참고 글

참고 글을 추가할 때는 아래 세 가지를 적는다. 참고 메모에서 글의 구조와 설명 방식을 적용하고, 본문 문장은 새로 쓴다. 링크와 메모는 작성 참고 자료로 사용하며, 링크의 내용을 확인했다는 근거로 사용하지 않는다.

- 글 제목과 URL
- 참고할 부분과 그 이유
- 이 블로그 글에 적용할 방법

### 구성 참고 예시

- 아는 만큼 보이는 이야기의 생활 IT 글은 설정이 필요한 독자를 먼저 짚고 실제로 막히는 지점과 확인 방법을 설명한다. 사용법 글에서는 대상과 환경을 초반에 밝히고, 단계별로 확인할 화면이나 결과를 적는다. https://21ilsang.tistory.com/
- 코밍로그의 번개장터 구매 글은 구매자가 실행하는 절차를 따라간다. 구매 가이드에서는 독자가 결정을 내려야 하는 지점에 확인 항목과 주의점을 둔다. https://gureum5.tistory.com/3
- 오픈코스의 Rainy75 리뷰는 무선 연결 방법과 사용하면서 느낀 불편을 구체적으로 다룬다. 제품 글에서는 일반적인 부품 설명보다 실제 구매나 설정에 필요한 질문을 우선한다. '책상에 놓았을 때 공간은 얼마나 필요한가', '유선과 무선은 어떻게 전환하는가', '구매 전에 어떤 구성을 확인해야 하는가'처럼 질문을 나눌 수 있다. https://www.opencourse.kr/rainy75-keyboard-preview/
