# 관리자 화면 기획 v1.0

공개 블로그의 최종 디자인은 [별도 디자인 기획](./public-blog-design-plan.md)을 따른다. 현재 공개 UI는 기능 검증용이며, 사용자 레퍼런스 수령 후 읽기·탐색·광고 배치를 검토해 운영 배포 전에 확정한다. 관리자 UI는 현재 방향을 유지한다.

기준일: 2026-11-02. 관리자 1명이 사용하는 단일 블로그 MVP를 기준으로 한다.
공개 블로그는 독자가 글을 읽는 별도 앱이며, 관리 기능과 AI 실행은 관리자 영역에 둔다.
이 문서는 목표 기능이다. 실제 구현 진행 상황은 [개발 TODO](./todo.md)에서 관리한다.

## 메뉴와 경로

| 메뉴 | 경로 | 역할 |
| --- | --- | --- |
| 대시보드 | `/` | 콘텐츠 현황과 처리할 작업 확인 |
| 게시글 | `/posts` | 직접 작성 글과 AI 생성 글을 함께 관리 |
| AI 글쓰기 | `/ai-writing` | 생성 요청, 진행 상황, 결과 및 실패 확인 |
| 카테고리 | `/categories` | 주제별 분류 관리 |
| 블로그 설정 | `/settings` | 블로그 기본 정보와 AI 작성 규칙 관리 |

게시글 하위 경로는 `/posts/new`, `/posts/[postId]/edit`, `/posts/[postId]/preview`로 계획한다.
하위 페이지에서도 게시글 메뉴를 활성 표시한다. 로그인 화면은 `(admin)` 레이아웃 밖에 둔다.
데스크톱은 사이드바와 상단 바, 모바일은 접을 수 있는 메뉴를 사용한다.
상단 바에는 현재 메뉴와 공개 블로그 바로가기를 둔다.

## 1. 대시보드

- 상단 작업: 직접 글쓰기, AI 글쓰기.
- 콘텐츠 요약: 전체 글, 발행 글, 초안 수. AI 연결 후 검토 대기 수 추가.
- 최근 수정 글: 제목, 카테고리, 상태, 수정일, 편집 바로가기. 최근 5개와 전체 목록 링크.
- AI 연결 후 작업 요약: 생성 중, 검토 대기, 실패 작업과 해당 작업 바로가기.
- 방문 통계·인기 글·유입 경로는 수집 기능을 연결한 뒤 추가한다. 미연결은 0으로 표시하지 않는다.
- 데이터가 실제로 없으면 첫 글 작성 안내, 불러오기 실패 시 오류와 재시도, 로딩 시 로딩 상태를 표시한다.

완료 기준: 실제 저장된 콘텐츠와 작업 수가 일치하고, 두 작성 경로 및 최근 글 편집으로 이동할 수 있다.

## 2. 게시글 목록

- 직접 작성 글과 AI 생성 글을 한 목록에서 관리한다. 작성 방식은 별도 표시한다.
- 열: 제목, 카테고리, 상태, 작성 방식, 수정일.
- 제목 검색, 상태·카테고리 필터, 최신 수정순 정렬, 페이지 이동.
- 새 글 작성, 기존 글 수정, 미리보기, 공개 글 보기.
- 삭제는 대상 제목을 보여주고 확인받는다. 일괄 작업은 후속 기능으로 둔다.
- 빈 목록과 검색 결과 없음은 구분하며 검색 조건 초기화를 제공한다.

완료 기준: 검색·필터·페이지 이동이 함께 동작하고, 글을 선택하면 해당 글 편집 화면으로 이동한다.

## 3. 글 작성·수정

- 기본 항목: 제목, 슬러그, 카테고리 1개(미분류 허용), 대표 이미지와 대체 텍스트, 본문.
- Tiptap 무료 기능: 문단, H2/H3, 굵게·기울임·취소선, 목록, 인용, 링크, 이미지, 구분선, 실행 취소·다시 실행.
- 제목은 공개 화면의 H1로 사용한다. 본문은 Tiptap JSON으로 저장하고 공개 앱에서 서버 렌더링한다.
- SEO 항목: SEO 제목·설명. canonical은 블로그 주소와 슬러그로 계산하며 임의 수정은 초기 범위에서 제외한다.
- 동작: 초안 저장, 미리보기, 발행, 발행 글 수정, 비공개 전환.
- 필수값 누락, 블로그 내 슬러그 중복, 저장·업로드 실패를 안내한다. 중복 저장을 막고 미저장 변경 이탈을 경고한다.
- 발행된 URL 변경은 별도 리다이렉트 정책이 필요하므로 초기에는 발행 후 슬러그를 잠근다.

완료 기준: 저장 후 다시 열어도 본문과 설정이 유지되고, 미리보기와 공개 본문 표현이 일치한다.

## 4. AI 글쓰기

- 입력: 키워드(필수), 카테고리(선택), 추가 작성 지시(선택).
- 블로그 설정의 주제·언어·말투·작성 규칙을 기본값으로 적용한다.
- 흐름: 키워드 → Main Agent 본문 생성 → SEO·QA·이미지·내부 링크 → 검토 대기 초안 → 수정·승인 → 발행.
- 결과 목록: 키워드, 작업 상태, 요청 시각, 초안 열기. 진행 화면에는 단계별 진행과 오류·재시도를 표시한다.
- 재시도는 동일 작업에서 이어가며 초안이나 이미지를 중복 생성하지 않도록 설계한다.
- AI 생성 결과도 공통 게시글 편집기에서 수정한다. 에이전트별 허용 필드만 반영한다.
- QA 실패·검증 미완료 글은 발행을 막는다. 검증 후 본문·이미지·링크 등이 변경되면 승인을 무효화하고 재검증한다.
- 최초 MVP에서는 생성 완료만으로 발행하지 않는다. 관리자가 결과를 확인하고 최종 승인한다.

완료 기준: 키워드 1개로 편집 가능한 초안이 생성되고, 단계별 실패 확인·재시도와 검수 후 발행이 가능하다.

## 5. 카테고리

- 이름, 슬러그, 설명, 표시 순서를 관리하고 소속 게시글 수를 표시한다.
- 생성·수정·삭제, 이름·슬러그 중복 검증을 제공한다. 초기에는 단일 계층만 지원한다.
- 게시글이 있는 카테고리는 바로 삭제할 수 없고 다른 카테고리 또는 미분류로 먼저 이동한다.

완료 기준: 카테고리가 편집기 선택 항목과 공개 블로그 분류에 일관되게 반영된다.

## 6. 블로그 설정

- 기본 정보: 블로그 이름, 소개, 언어, 공개 주소 확인.
- AI 작성 설정: 주제, 대상 독자, 말투, 작성 규칙, 피해야 할 표현.
- 저장·저장 중·성공·오류 상태를 구분한다.
- 공개 주소는 배포 설정과 맞아야 하므로 초기 UI에서는 읽기 전용이다.
- API 키 등 비밀값은 이 폼에서 다루지 않는다. 다중 블로그 선택은 후속 단계에 추가한다.

완료 기준: 저장한 설정이 다시 표시되고 공개 메타데이터와 이후 AI 생성 요청에 반영된다.

## 상태와 접근 규칙

- 게시글 공개 상태: `draft`(초안), `published`(발행), `private`(비공개).
- AI 작업 상태: 대기, 실행 중, 검토 대기, 실패, 완료. 단계별 검증 결과는 공개 상태와 별도로 관리한다.
- AI 생성 완료는 검토 대기를 뜻하며 게시글은 초안으로 유지한다. 승인된 최신 버전만 발행한다.
- 공개 앱은 발행된 글만 조회한다. 초안 미리보기 및 관리 API는 관리자 인증으로 보호한다.
- UI 단계에서는 준비 화면을 표시하고 실제 저장·생성이 되는 것처럼 표시하지 않는다.
- 통계 미연결, 로딩, 데이터 없음, 오류를 구분한다. 실제 관리자 데이터 API 공개 전에 인증을 연결한다.

## 후순위

방문 통계, 댓글·회원 인증, 구독, 예약 발행, 여러 블로그 운영, 키워드 자동 발굴, 대규모 병렬 생성.
데이터에는 처음부터 `blogId`를 포함하지만 다중 블로그 운영 UI는 초기 범위에 넣지 않는다.
