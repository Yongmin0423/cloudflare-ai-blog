# AI 글쓰기 품질 개선 기록

이 문서는 키워드 기반 초안에서 발견한 문제, 적용한 생성·검증 규칙, 이후 서브 에이전트 개발에 사용할 기준을 기록한다. 일상적인 집필 원칙은 [글쓰기 가이드](../workers/agent-service/src/editorial-guide.md), 실행 방법은 [Agent Service 안내](../workers/agent-service/README.md)를 참고한다.

## 개선 전 관찰한 문제

| 관찰한 현상                                                               | 당시 확인한 원인과 근거                                                                                                                                                                                                         |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 영화가 게임으로 바뀌거나 다른 작품의 날짜·배역이 섞였다                   | 키워드만으로 대상과 내용을 추정하면 이름이 비슷한 작품이나 주변 문맥을 끌어올 수 있었다. 사용자가 올린 이전 초안에는 출처 없이 단정한 날짜와 줄거리가 있었다.                                                                   |
| 원문에 명단이 있는데도 “확인하기 어렵다”고 썼다                           | 목차 단계에서 뽑은 근거와 요약만 집필에 전달하면, 원문을 읽었어도 해당 문단이 집필 단계에 도달하지 않을 수 있었다. 이를 모의 응답에서 재현했다.                                                                                 |
| 국가별 개봉일과 특별관 안내가 뒤섞였다                                    | 원문 예시에서는 국가가 국기 이미지로 표시됐고, 같은 페이지에 국가별 개봉일 표와 별도의 상영 형식 표가 있었다. 기존 추출기는 이미지의 대체 텍스트를 버렸다. 당시 모델이 실제로 어떤 문단을 인용했는지는 로그로 확인할 수 없었다. |
| 날짜는 확인됐는데 ‘개봉일과 상영 형식’이라는 소제목에서 저장이 막혔다     | 하나의 소제목이 서로 다른 근거가 필요한 두 질문을 묶었다. Wrangler 로그에서 재작성 후에도 QA가 그 소제목을 `missing_answer`로 판단하고 502를 반환한 것을 확인했다.                                                              |
| 소제목마다 답이 한두 문장이거나 “목록에는 배역이 없다”는 말로 끝났다      | 초기 집필 지시는 목차의 답변 요약을 한 문단으로 풀어 쓰도록 유도했고, QA는 질문에 답했는지를 중심으로 판단했다. 마지막으로 공유된 예시는 소제목과 인용을 제외하고 공백을 포함해 760자였다.                                      |
| “AI 응답이 초안 형식에 맞지 않아요”가 뜨면서 어디서 막혔는지 알 수 없었다 | 대상 확인·목차·본문·QA가 같은 오류 문구를 공유했다. 실제 실패 응답의 원문과 세부 단계는 남아 있지 않았다.                                                                                                                       |

## 현재 초안 생성 흐름

1. **대상 확인.** Workers AI가 키워드에서 글 대상의 이름과 유형을 제안한다. 관리자가 확인한 대상과 D1에 저장한 블로그별 언어·독자·말투·작성 규칙을 이후 단계에서 사용한다.
2. **출처 수집.** 로컬에서 연결한 ChatGPT 모델이 웹 검색한다. 추가 작성 지시를 검색에 전달하고, 관리자가 넣은 공개 HTTPS URL 최대 5개와 검색 결과를 함께 읽는다. 같은 주소는 중복을 제거한다. 공식 원문을 우선하고, 원문을 찾기 어려울 때는 해당 기관의 발표를 명시적으로 인용한 보도를 귀속과 함께 사용한다. 위키는 조사 단서로 쓴다. Worker의 별도 Ceramic 검색 경로는 설정으로 활성화한다.
3. **목차와 근거 추출.** Workers AI가 서로 독립적으로 답할 수 있는 질문을 소제목으로 잡는다. 원문에서 문단·표 셀의 경계와 표 안 이미지 대체 텍스트를 보존한다. 국가·모델·버전·시점이 중요한 사실은 같은 범위의 원문 근거와 연결한다.
4. **소제목별 근거 검색과 집필.** 읽은 페이지를 문단으로 나누고 Workers AI의 BGE-M3 임베딩으로 질문별 관련 문단을 최대 4개 고른다. 로컬 경로에서 선택한 ChatGPT 모델이 목차와 원문을 사용해 본문을 쓴다. 자료가 충분할 때 한국어 본문 1,200~1,800자를 목표로 하며, 공식적으로 공개된 배역처럼 독자가 원하는 구체적인 정보를 먼저 설명한다.
5. **QA와 저장.** Workers AI가 제목·소제목·본문의 주장과 인용을 대조한다. 답변이 빠졌으면 한 번 재작성한다. 복합 질문의 일부만 확인되면 검증된 답을 활용한다. 선택적 분량 보강에서 근거가 약해지면 먼저 검증된 버전을 쓴다. 필수 답변 누락이나 근거 충돌이 남으면 저장을 중단한다. 형식 오류는 해당 단계에서 재시도하고 최종 오류에 단계를 표시한다. 통과한 글은 원문 링크가 붙은 Tiptap 초안으로 D1에 저장된다.
6. **사람이 편집.** 로컬 게시글 수정 화면에서 **AI로 다듬기**를 열어 문단을 고르거나, 미리 선택한 문장의 수정안을 현재 초안의 주변 문맥으로 받는다. 문단 끝의 인용 링크는 편집 범위에서 제외한다. 관리자가 비교 후 적용하고 직접 저장한다. 이 단계에서 추가 웹 검색은 실행하지 않는다.

구현 위치는 [Agent 생성](../workers/agent-service/src/generate-draft.ts), [출처 읽기](../workers/agent-service/src/research-sources.ts), [문단 검색](../workers/agent-service/src/section-evidence.ts), [편집기 AI 수정](../apps/admin-web/src/features/posts/ai-revision.tsx)이다.

## 검증 상태와 다음 판단

- [x] 모의 응답으로 출처 병합·인용, 국가와 제품 버전이 섞인 주장 차단, 원문에 있는 답변 누락의 재작성, 부분 답변의 보강, 깨진 JSON과 누락된 QA 응답 재시도 확인
- [x] 관리자·Worker 타입 검사와 변경 관리자 코드 린트 확인
- [ ] 로컬 관리자에서 실제 계정으로 검색·본문 생성·D1 저장·인용 열기·AI 수정안 적용과 저장까지 같은 버전에서 다시 확인
- [ ] 영화, 제품 비교, 생활 안내처럼 자료 유형이 다른 입력을 기준으로 출처의 정확성, 독자 질문에 대한 답변 범위, 저장 성공 여부, 생성 시간을 비교

**발행 전 QA**는 관리자가 수정해 저장한 최신 버전의 본문과 인용을 검토하고, 통과 결과를 해당 버전에 연결한다. 실제 관리자 화면에서 QA부터 발행까지 확인하는 절차와 이후 SEO·이미지·내부 링크 작업은 [다음 개발 작업](./next-steps.md)을 참고한다.
