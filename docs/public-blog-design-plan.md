# 공개 블로그 디자인 기획 — 수익화 운영 준비

기준일: 2026-11-03

## 현재 디자인의 위치

현재 공개 블로그의 '기록의 숲' 이름, 일러스트, 색상, 추천 글과 카드 배치는 기능과 데이터 흐름을 확인하기 위한 임시 디자인이다. 수익화 운영용 최종 디자인으로 확정한 상태가 아니다.

관리자 UI는 현재 방향을 유지한다. 공개 블로그는 사용자가 제공할 레퍼런스를 바탕으로 별도 디자인 작업을 진행한다. 데이터 구조·D1 작업은 레퍼런스가 없어도 계속 진행하며, 최종 공개 디자인은 운영 배포 전에 검토·확정한다.

## 레퍼런스 수집과 검토

- 사용자가 블로그 링크 또는 화면 캡처와 선호하는 부분을 제공한다.
- 홈·목록·글 상세·모바일 화면 중 어떤 화면을 참고할지 구분한다.
- 정보 구조, 본문 폭, 글자 크기와 줄 간격, 목차, 카테고리·검색·관련 글, 사이드바, 광고 영역을 비교한다.
- 레퍼런스의 배치 원리를 참고하고 프로젝트의 콘텐츠와 독자에 맞게 재구성한다. 로고·본문·이미지는 그대로 복제하지 않는다.
- 레퍼런스의 실제 수익은 확인된 자료가 없는 한 추정하지 않는다. 디자인만으로 같은 수익이 발생한다고 판단하지 않는다.

## 디자인 목표

### 읽기와 탐색

- 모바일에서 본문을 편하게 읽을 수 있도록 글자 크기·줄 간격·문단 간격·본문 폭을 조정한다.
- 카테고리, 검색, 목차, 관련 글을 통해 원하는 정보와 다음 글로 이동하기 쉽게 구성한다.
- 제목·요약·대표 이미지·날짜의 우선순위를 정리해 목록에서 글 내용을 파악할 수 있게 한다.
- 사이드바 사용 여부와 추천 글·인기 글의 위치는 레퍼런스와 실제 콘텐츠 분량을 보고 결정한다.
- 검색·인기 글 등 아직 연결되지 않은 기능은 최종 디자인에 필요한 UI와 기능 TODO를 함께 추가한다.

### 광고 영역

- 홈·목록·상세별 광고 후보 위치를 모바일과 데스크톱에서 각각 검토한다. 위치와 개수는 아직 확정하지 않는다.
- 광고와 콘텐츠, 메뉴·버튼을 구분하고 본문 읽기 흐름을 유지한다.
- 광고 로딩으로 화면이 크게 밀리지 않도록 영역 크기와 로딩·미노출 상태를 설계한다.
- 광고 미연결 상태와 실제 광고 연결 상태를 구분해 확인한다. 현재 단계에서 광고 계정·스크립트를 연결하지 않는다.
- 실제 광고 도입 시 선택한 광고 서비스의 당시 공식 정책을 확인하고 배치를 검증한다.

## 구현 경계

- 게시글 본문(Tiptap JSON), 제목, 분류 등 콘텐츠 데이터와 공개 화면의 배치·스타일을 분리한다.
- 광고 코드를 게시글 본문 JSON에 섞지 않는다. 광고 영역은 공개 앱의 별도 컴포넌트로 관리한다.
- 블로그별 테마·표시 설정이 필요하면 블로그 설정과 분리된 표현 계층으로 설계한다. 첫 데이터 모델에 임의의 CSS/HTML 저장 기능을 추가하지 않는다.
- 관리자와 공개 앱의 화면·스타일 독립성을 유지한다.
- 디자인 변경 후에도 발행 상태 필터, 슬러그/URL, 본문 구조, 접근성 및 SEO 메타데이터를 유지·검증한다.

## 진행 순서와 완료 기준

1. 레퍼런스 수령 → 참고 화면과 선호 요소 정리.
2. 홈·목록·카테고리·상세의 PC/모바일 배치안과 광고 후보 위치 작성.
3. 사용자가 배치안을 확인한 뒤 공개 앱 디자인 적용.
4. 긴 제목·긴 본문·이미지 없는 글·빈 목록·광고 미노출 상태 점검.
5. 모바일 가독성, 키보드 탐색, 내부 링크, 레이아웃 이동 및 로딩 성능 확인.
6. 운영 배포 전 최종 디자인 확정. 실제 광고 연결과 수익 측정은 별도 운영 작업으로 진행.

실제 독자와 콘텐츠에 맞는 공개 화면을 확인하고 위 검증을 마치면 디자인 단계를 완료한다. 광고 승인·검색 순위·수익 달성은 이 디자인 단계의 완료 기준에 포함하지 않는다.
